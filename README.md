# opencode Sidebar

Расширение VS Code, которое добавляет **иконку opencode в левую панель Activity Bar** — туда, где находятся иконки других расширений.

Официальное расширение `sst-dev.opencode` не создаёт собственную панель: оно только открывает opencode в отдельной вкладке редактора (`ViewColumn.Beside`). Поэтому его иконки в Activity Bar нет и включить её настройкой нельзя. Это расширение открывает **официальный web-интерфейс opencode прямо в левой панели сразу при её открытии** — без стартового экрана и отдельного терминала. Сверху панели находятся вкладки сессий.

> Это неофициальное расширение. Оно не связано с проектом opencode и его авторами и использует его официальный web-UI через локальный прокси.

Сейчас расширение распространяется через [GitHub Releases](https://github.com/mvkorolenko90-wq/opencode-sidebar/releases). Публикация в VS Code Marketplace и Open VSX — в планах.

## Что внутри

| Файл | Назначение |
|---|---|
| `package.json` | Манифест: иконка в Activity Bar, webview-панель, команды. |
| `extension.js` | Панель, вкладки, встроенные iframe и запуск терминала. |
| `webui.js` | Локальный прокси к сервису opencode и автоподключение web-UI. |
| `media/opencode.svg` | Монохромная иконка для Activity Bar. |
| `media/panel.js` | Скрипт панели (вкладки, iframe, сообщения). Подключается через `asWebviewUri`: inline-скрипт в webview не выполняется. |
| `telegram.js` | Поиск папки opencode-telegram, статус и управление ботом без зависимости от `vscode`. |
| `updates.js` | Проверка релизов на GitHub, сравнение версий и скачивание VSIX для кнопки обновления. |
| `install.sh` | Сборка VSIX и установка в VS Code. |
| `update.sh` / `update.ps1` | Обновление до последнего релиза с GitHub (Linux/macOS и Windows). |
| `agents/` | Агенты для «Рекомендуемого»: JSON вливается в конфиг opencode. |
| `skills/` | Скиллы для «Рекомендуемого» и их `manifest.json`. |
| `tests/` | Тесты панели без обращения к модели (`node --test`). |

## Как это работает

1. При открытии панели расширение находит запущенный фоновый сервис opencode (`opencode service status`), при необходимости запускает его.
2. Берёт пароль сервиса (`opencode service get password`).
3. Поднимает локальный HTTP/WebSocket-прокси на `127.0.0.1` и отдаёт официальный web-UI opencode в iframe внутри панели.
4. Каждая вкладка панели — отдельный iframe с web-UI opencode. Поэтому несколько сессий могут работать одновременно.
5. В HTML web-UI добавляется конфигурация сервера, поэтому подключение происходит автоматически — без экрана «Подключиться к серверу» и без ручного ввода пароля.

Прокси работает только на localhost и не открывает доступ из сети. Пароль не пишется в логи.

## Установка

Требования: VS Code 1.94+. CLI `opencode` можно не устанавливать заранее — если его нет, панель покажет кнопку «Установить opencode» и поставит официальным установщиком (на Linux/macOS — `curl -fsSL https://opencode.ai/v2/install | bash`, на Windows — готовый бинарник). Node.js и npm для этого не нужны.

1. Скачайте `opencode-sidebar-<версия>.vsix` со страницы [Releases](https://github.com/mvkorolenko90-wq/opencode-sidebar/releases/latest).
2. Установите файл:

```bash
code --install-extension opencode-sidebar-<версия>.vsix --force
```

В Windows используйте `code.cmd`:

```powershell
code.cmd --install-extension .\opencode-sidebar-<версия>.vsix --force
```

3. Перезагрузите окно VS Code: `Ctrl+Shift+P` → `Developer: Reload Window`.

Иконка opencode появится в Activity Bar слева. Если её не видно, нажмите `...` в Activity Bar (туда сворачиваются лишние иконки) или выполните команду `View: Show opencode`.

### Обновление

Расширение не обновляется само: оно распространяется через GitHub, а не через VS Code Marketplace. Когда выходит новая версия, запустите скрипт обновления из папки проекта.

Linux/macOS:

```bash
bash update.sh
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\update.ps1
```

Скрипт берёт последний релиз, сравнивает версию с установленной и, если она старше, скачивает VSIX и ставит его с `--force`. Если версия уже последняя, ничего не делает. Аргумент задаёт конкретную версию, `--force` / `-Force` — переустановку текущей:

```bash
bash update.sh 0.9.24 --force
```

```powershell
.\update.ps1 -Version 0.9.24 -Force
```

После установки перезагрузите окно VS Code: `Ctrl+Shift+P` → `Developer: Reload Window`. Проверить версию: `code --list-extensions --show-versions | grep opencode-sidebar`.

Вручную то же самое: скачайте `opencode-sidebar-<версия>.vsix` со страницы [Releases](https://github.com/mvkorolenko90-wq/opencode-sidebar/releases/latest) и выполните `code --install-extension opencode-sidebar-<версия>.vsix --force`.

### Если иконка не появилась

1. Выполните `Ctrl+Shift+P` → `Developer: Reload Window`.
2. Проверьте, что расширение включено: `Extensions` → `@installed opencode Sidebar`.
3. Если в Activity Bar мало места, лишние иконки скрываются в `...`; перетащите opencode из этого меню на панель.
4. Команда `View: Show opencode` должна открыть панель.
5. Если панель показывает ошибку загрузки, нажмите «Повторить» или кнопку `⟳` в заголовке панели.

## Как пользоваться

- Клик по иконке opencode сразу открывает web-интерфейс opencode в панели. Стартового экрана с кнопками и полосы с заголовком нет.
- Первый запуск может занять несколько секунд: расширение поднимает локальный прокси и подключается к сервису opencode.
- Сверху панели — вкладки. Кнопка `+` или `Ctrl+Shift+T` создаёт новую вкладку с главным экраном opencode. В каждой вкладке можно открыть свою сессию; вкладки работают параллельно.
- Название вкладки — имя сессии из API opencode, а не «Главная». Пока сессия новая и имени нет, остаётся подпись по умолчанию.
- Вкладки можно перетаскивать мышью, порядок сохраняется до перезагрузки окна.
- Переключение — клик по вкладке; закрытие — `×` на вкладке. Название вкладки обновляется по имени сессии.
- Индикация ответа: пока модель работает, у вкладки мигает жёлтая точка; когда ответ пришёл, а вы были в другой вкладке, вкладка становится зелёной. Открытие вкладки сбрасывает цвет.
- В правой части панели вкладок показывается стоимость текущей сессии (`$0.18`), если провайдер отдаёт цену через API. В подсказке — вход, выход и кэш токенов.
- Внизу панели, под чатом — переключатель агента. Он меняет агента и в текущей сессии, и глобально: выбранный агент записывается в `default_agent` в `~/.config/opencode/opencode.json` (с бэкапом) и применяется через `opencode reload`, поэтому новые сессии и TUI стартуют с него же. Список берётся из `/api/agent` (только primary, кроме hidden). Рядом кнопка `модель`: берёт модель текущей сессии (её выбирают в композере) и делает её глобальной, записывая `model` в тот же конфиг. Reload при этом откладывается, пока идёт ответ, чтобы не прервать ход.
- Рядом кнопка `Graphify` — появляется только если скилл graphify установлен (глобально или в проекте). Нажатие отправляет в текущую сессию запрос с прикреплённым скиллом: построить граф по проекту или обновить существующий `graphify-out`.
- В правом нижнем углу панели — кнопка `⬆` обновления расширения. Нажатие проверяет последний релиз на GitHub: если версия новее установленной, она скачивает VSIX и ставит его с `--force`, после чего VS Code предлагает перезагрузить окно. `⟳` во время проверки, `⤓` при скачивании и установке, `✓` — версия актуальна, красный цвет — ошибка (подсказка показывает причину). Проверка не запускается сама: только по нажатию.
- Кнопка `⤢` в полосе вкладок и команда **opencode: Открыть на весь экран** открывают тот же интерфейс отдельной вкладкой в области редактора — на всё окно. В полном окне доступны добавление вкладок (`+` и `Ctrl+Shift+T`), «Рекомендуемое», обновление расширения, выбор агента и модели, Graphify и сжатие контекста. Боковая панель при этом скрывается. Кнопка **⤡ В панель** стоит в верхней полосе, не перекрывая чат; она (или закрытие вкладки) возвращает маленькую панель с прежними вкладками. Используется уже запущенный прокси и текущий адрес активной вкладки; повторное нажатие переключает на открытую полноэкранную панель.
- Кнопка `★` в панели вкладок открывает «Рекомендуемое»: нумерованный список скиллов и агентов с описанием и кнопкой установки. Скилл копируется в `~/.config/opencode/skills/<name>/`; агент вливается в `~/.config/opencode/opencode.json` (с бэкапом `opencode.json.bak-<timestamp>`). Агентам после установки нужен `opencode reload`. Статус «установлен» учитывает требования из `skills/manifest.json` (`requires`): CUA Driver — драйвер `cua-driver` и MCP в конфиге opencode, Graphify — программа `graphify` (если нет `uv`, он ставится первым), Find Skills — `npx` (если нет Node.js, он ставится в `~/.local/node` на Linux или `%LOCALAPPDATA%\node` на Windows). Недостающие зависимости видны сразу, даже до установки пакета. Кнопка называется «Установить с зависимостями» и сначала раскрывает подтверждение со списком того, что будет поставлено; «Установить всё» ставит зависимости по порядку, затем сам пакет и перепроверяет статус. Список закрывается по `Esc`, `×` или клику вне его области, в том числе по вкладке.
- Строка **Telegram-бот** там же: пока бот не установлен, у неё поля «Токен от @BotFather» и «Telegram ID (цифры)» и кнопка «Установить». Установка идёт из панели: расширение сохраняет токен и ID в `~/.config/opencode-telegram-bot/.env` (права 0600) и запускает установщик без терминала. Перед этим проверяются Node.js 22.14+, CLI `opencode` и выбранная модель: если чего-то нет, вместо формы показывается «Установить в терминале» — установщик поставит Node/OpenCode (нужен sudo) и спросит модель. После установки на её месте появляются кнопки `▶ Запустить`, `⏹ Остановить`, `🔄 Перезапустить`, `🚀 Автозапуск`, `📊 Статус` и обновление состояния `↻`; они управляют ботом через его CLI и скрипт `start.ps1`/`start.sh`. Автозапуск: `HKCU\...\Run` (Windows) или служба `systemd --user` (Linux). Папка ищется в настройке `opencodeSidebar.telegramPath`, затем в рабочей папке и `~/opencode-telegram`. Те же действия есть в палитре команд: «Telegram-бот: …».
- Если opencode не установлен, панель показывает это в ошибке и предлагает кнопку «Установить opencode». Она ставит официальный CLI без Node.js: на Linux/macOS через `curl -fsSL https://opencode.ai/v2/install | bash`, на Windows — готовым бинарником в `%LOCALAPPDATA%\opencode\bin`. После установки выберите модель и нажмите «Повторить».
- Рабочая папка VS Code автоматически добавляется в проекты opencode. Открывать её повторно через «Добавить проект» в web-UI не нужно — можно сразу создавать первую сессию.
- Web-UI хранит проекты и настройки в localStorage своего адреса, поэтому прокси всегда поднимается на одном и том же порту для рабочей папки. После перезагрузки панели список проектов и открытые вкладки сохраняются; если порт занят другим окном, берётся случайный и состояние этого окна начинается заново.
- В панели вкладок слева появляется `←` на маршруте сессии — она открывает главный экран **в этой же вкладке**, не создавая новую и не перезагружая сессию в других вкладках.
- Ссылки и окна авторизации (`Open browser` при подключении провайдера, OAuth) открываются в системном браузере, а не теряются внутри панели: webview не умеет открывать новые окна, поэтому расширение перехватывает их и передаёт ссылку в ОС. Работает и в боковой панели, и в полноэкранном режиме.
- В заголовке панели две кнопки: `⟳` — перезагрузить интерфейс, терминал — открыть обычный TUI в нижней панели.

Горячие клавиши официального расширения продолжают работать: `Ctrl+Esc`, `Ctrl+Shift+Esc`, `Ctrl+Alt+K`.

### Ctrl+Shift+T

VS Code сам занимает `Ctrl+T` («Go to Symbol in Workspace»), поэтому webview это нажатие не получает. Расширение объявляет команду `opencodeSidebar.newTab` с привязкой `Ctrl+Shift+T` и условием `opencodeSidebarOpen`: этот контекстный ключ выставляет само расширение, пока панель видима, поэтому привязка не зависит от того, где стоит фокус. Пока панель opencode видна, эта комбинация не переоткрывает закрытые редакторы — это осознанный компромисс.

Индикация ответа строится на событиях сервиса opencode (`/api/event`), а не на изменениях DOM, поэтому вкладка не зеленеет, пока модель ещё думает.

### Если агент не отвечает

- Проверено: ответы через встроенный web-UI приходят, прокси не блокирует поток. Если в сессии видно «Прервано» или запрос завис, открой новую вкладку `+` и начни новую сессию.
- Не нажимай `⟳` в заголовке панели и не перезагружай окно VS Code во время ответа: это прерывает текущий ход. Переключение вкладок и стрелка `←` безопасны — они не перезагружают сессию и не прерывают ответ.
- Проверь выбранную модель в композере. Если модель не отвечает, переключись на другую рабочую модель.
- Старую сессию можно оставить в другой вкладке — новые вкладки не прерывают её.
- Если не отвечают все сессии, проверь `opencode service status` и при необходимости перезапусти сервис: `opencode service restart`.

## Сборка из исходников

```bash
git clone https://github.com/mvkorolenko90-wq/opencode-sidebar.git
cd opencode-sidebar
npm run check
npm run package
code --install-extension ./opencode-sidebar-<версия>.vsix --force
```

`install.sh` делает то же самое одной командой.

Тесты проверяют обработку сжатия, отключение прежнего плагина итогов и разметку панели без обращения к модели. `.research/` и тесты не попадают в VSIX.

Удалить расширение:

```bash
code --uninstall-extension myai.opencode-sidebar
```

## Ограничения

- Кнопка «Сжать контекст» под чатом вызывает штатное сжатие контекста opencode в той же сессии. Во время ответа кнопка недоступна. Подтверждение запроса не означает завершение сжатия: его ход и результат отображаются в чате. Сжатие может потерять детали переписки, но не изменяет файлы проекта.
- Карточка итогов и связанный инструмент завершения удалены. При первом запуске новой версии старый плагин `~/.config/opencode/plugins/opencode-sidebar-completion.js` переименовывается в резервный файл `.disabled-<время>`: его инструмент и системная инструкция больше не загружаются. Неизвестный файл без идентификатора нашего плагина не изменяется.

- Встроенный режим использует официальный **web-UI** opencode, а не TUI. Для терминального интерфейса нажмите кнопку терминала в заголовке панели.
- Каждая вкладка — полная копия web-UI opencode, поэтому много открытых вкладок расходует память. Закрывайте неиспользуемые.
- Если opencode изменит формат хранения настроек web-UI, автоподключение может потребовать обновления расширения.
- Прокси и iframe рассчитаны на локальный VS Code. В remote-окне используется `asExternalUri`; если порт не пробрасывается, используйте терминальный режим.
- Проверка CLI выполняется через login-shell; при нестандартном PATH запуск всё равно работает через терминал.
